# Charcoal audit, 2026-10-13

A deep audit of the whole program (about 10,700 lines) at commit a676cfe.

**Status: all fixed the same evening**, except two left on purpose: the BBC double-height rule (#11 under
"meh"; not verified) and HiDPI (part of the Mac port). Not handled either: a character in the very last
cell of a C64/Atari screen still makes the real machine scroll. Checked after the fixes: `go test`
(new tests for each finding), `FuzzParsers` (every reader, any length, time and size limits), the big check
(8196 files, the same result as before) and headless runs of the worst files.

How it was done: three reviewers read the code (file formats, machine pages, editor and interface), and
the parsers were fuzzed (6.3 million random files, with a 6 GB memory cap). `go vet` is clean and
`go test` passes; test coverage is 31%.

**Verified** = made to happen (a test, the fuzzer or a headless run). **Read** = seen in the code, not
run. **Proposed** = believed from documentation, not tested.

## Meh (risks and rough edges)

- Undo copies the whole page per keystroke, and dropped undo steps stay in memory (about twice the 64 MB
  budget per tab). Undo always marks the page changed, and Fill marks it changed even when nothing changes.
- Saving replaces a symlink with a plain file, and fails in a folder you cannot write to (editor.go:1749).
- The same tab can end up in both split panes after closing a tab; drawing then lands in the wrong cells.
- F-keys and arrows reach the page while the W/H field has focus.
- A broken prefs.json is silently replaced by defaults. The editor and viewer overwrite each other's settings.
- Downloads freeze the window (up to 160 s) instead of running in the background.
- XBin height wraps above 65535 rows; SAUCE notes are lost on save; SAUCE text is read as Latin-1, not CP437.
- ESC Y on the ST is not clamped (a 224-row page); edit.tf loses its character set; TTI ESC with a low byte;
  1024-byte Mode 7 dumps not recognised; BBC double height follows the broadcast rule.
- The viewer rebuilds its shrunk image every frame while playing.
- Windows: AltGr is seen as Ctrl, so @ { [ \ $ | ~ could not be typed on a Swedish keyboard (fix before the port).

## Nits

Dead code (`var _ = strings.TrimSpace`, `var _ = fmt.Sprint`, `luma`, `keyNames`, `Click.double`);
help and comments still say "Amiga, PC and C64"; Settings offers scale 1-3 but 4 is allowed; Atari/ST/ZX/
teletext start-up modes are not restored; tabs past the window edge cannot be reached; regexes compiled on
every call in parseMarq; the viewer's `e` leaves a zombie process; no HiDPI flag yet (needed for the Mac).

## The good

- Idle it uses about 1% CPU (it waits for events), 86 MB with a file open; one texture, no SDL leaks.
- Only the visible cells are drawn; a redraw takes about 1.5 ms.
- Downloads: HTTPS, pinned SHA-1 and size, size-limited reads, atomic writes, a pinned EmuTOS commit.
- No out-of-range reads in the ROM, ZX bitmap, EP1, edit.tf or TTI code; `Doc.get` is always safe.
- Teletext attributes, held graphics and sixels are right; the ZX bitmap layout is right.
- The cell layout is one clean 32-bit word; the BIOS colour table is its own inverse.
- `writeAnsi` writes colours only where they change and round-trips exactly.
- The XBin decompressor guards every read; parseMarq and parsePrg limit sizes.
- Clear immediate-mode UI code, a useful headless script harness, careful clipboard handling.

## Missing tests

No test feeds hostile input; nothing tests sizes (huge numbers, empty or short files), SAUCE on
iCEDraw/ArtWorx/Tundra, blink in round trips, .bin edge cases, or downloads (bad SHA, 404, cut-off body).
A fuzz test over all parsers with a memory limit would have caught 1, 2, 6, 9 and 24.
